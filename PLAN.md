# Plan: QuestMark spatial glass design refinement
_Locked via grill — by Codex + Ted_

## Goal
Refine QuestMark’s existing pearl-and-water spatial interface using the three supplied references without changing product behavior: preserve the orbit metaphor and real-world quest flow, introduce a quieter iridescent layered-glass system, give each app section a distinct and noticeable entrance, add restrained native scroll reveals, and restyle XP and achievements as clearer collectible progress objects.

## Approach
1. Reuse the existing shell, four-tab navigation, orbit stage, quest/proof cards, skill map, profile panels, design tokens, Manrope asset, and current light/dark themes. Make no data, XP-calculation, achievement-condition, location, evidence, privacy, or completion-flow changes.
2. In `src/app/questmark-app.tsx`, make only these markup and UI-state changes: add a visible-on-focus skip link and a programmatically focusable `main` target; identify Proof and Growth view roots; give each view `h1` a stable ID and `tabIndex={-1}`, then focus that heading after an explicit navigation activation; expose the active navigation item with `aria-current`; add separate progressbar semantics for level XP (`0..needed`, current `remaining`) and selected-skill score (`0..100`, current `score`) with distinct labels; keep locked achievements keyboard-focusable with `aria-disabled` and a guarded action; and clear the visual-only `newAchievements` marker after the user leaves Growth so its shimmer does not replay indefinitely.
3. In `src/app/globals.css`, edit existing declarations in place: base `:root` tokens and `body` typography/background where required, plus selectors already present in the approved spatial section. Add only the minimal missing rules for the skip link, Proof/Growth view roots, shared entrance keyframe, positive scroll-timeline feature query, and forced-colors fallback inside that existing approved section; do not append another replacement layer. Touch only headings, `.topbar`, `.bottom-nav`, `.page-wrap`, the four view roots, `.spatial-stage`, mission/quest/proof cards, `.skill-map`, `.skill-node`, `.progress-track`, `.achievement-list`, dialogs, focus, and accessibility media queries. Remove any superseded declaration in a touched rule when replacing it. Use pearl/water-blue with warm ivory support, deep-teal actions, restrained lilac/coral/mint signals, Manrope for body/control/utility text, and the Apple-style system face for display headings.
4. Refine the existing desktop rail/mobile bottom bar into one floating glass capsule. Use a local pseudo-element on each existing button for an iridescent active-edge scale/fade and soft glow; do not add cross-item indicator markup or navigation state machinery.
5. Keep the orbit as the Quests screen’s single visual anchor. Give mission cards and controls layered translucent planes, crisp borders, subtle depth, and high-contrast primary actions. Reserve iridescence for selected, active, primary, and milestone states.
6. Apply one shared material system across all four views while preserving distinct anchors. Reuse one entrance keyframe controlled by per-view CSS variables: Quests rises from the orbit; Proof uses a shallow deal tilt; Growth blooms from the center; Profile sheets slide and settle. The view wrapper owns entry motion; its descendants and SVG links must not receive a simultaneous entrance animation.
7. Add native CSS scroll-driven reveals only to below-fold descendants not used by the view entrance. Content remains fully visible by default; both the hidden initial state and the `24px` opacity/transform reveal live inside a positive `@supports (animation-timeline: view())` block. Avoid continuous parallax.
8. Restyle existing XP surfaces as semantic, luminous glass progress rails with clearer level/threshold contrast and one finite light pulse on Growth entry. Restyle existing achievement buttons as collectible glass medallions: earned items settle into place, the existing `newly-earned` marker receives one finite shimmer until Growth is left, and locked items remain focusable but visibly muted. Preserve current sound, XP calculations, and unlock conditions.
9. Keep routine control feedback at `160–220ms`, section entrances near `700ms`, and lifts within `2–5px`. Extend the existing reduced-motion and reduced-transparency branches so content, navigation state, XP, and achievements remain complete without motion or blur.
10. Apply the current Web Interface Guidelines while touching the UI: retain semantic buttons/labels, a visible skip-link focus state, visible `:focus-visible`, 44–48px targets, meaningful live regions, transform/opacity-only animation, dark-mode contrast, and mobile safe-area spacing. Add `prefers-contrast: more` and `forced-colors: active` rules that preserve borders, focus, active navigation, XP progress, and earned/locked distinctions. Provide solid-color defaults first and enhance blur/color mixing only where supported; retain the existing reduced-transparency branch.
11. Run only the smallest relevant verification after implementation: `npm run lint` and `npm run build`. Inspect the affected route in one browser at approximately 390px, 900px, and 1440px plus one 200% zoom reflow check. Verify keyboard focus transfer, skip-link operation, no horizontal overflow, console errors, reduced motion, and manual contrast of touched text/actions/progress/earned/locked states in both themes. Temporarily disable the positive scroll-timeline `@supports` block in browser DevTools and confirm all content remains visible. Do not add a cross-browser suite or new test dependency.

## Key decisions & tradeoffs
- Preserve QuestMark’s established pearl/water spatial identity; the references contribute edge, layering, and navigation treatment rather than replacing the product metaphor.
- Warm ivory supports the pearl base; it does not become a generic beige redesign. Deep neon appears only in dark mode and active states.
- Glass remains structural, not universal. Ordinary surfaces stay calm; iridescence marks active navigation, selected skills, primary actions, XP, and earned achievements.
- Motion is noticeable at view entry and scroll thresholds but restrained during routine work. One wrapper-owned keyframe plus per-view variables keeps the implementation small and prevents competing transforms. No parallax, animation package, new asset, or new dependency.
- Use the existing approved CSS override area instead of appending a third design generation. Full historical CSS consolidation is intentionally deferred because it conflicts with the smallest-change scope.
- Use native CSS scroll timelines progressively; unsupported browsers receive the complete static layout rather than JavaScript observation code.
- Skip link, XP semantics, active navigation state, locked-achievement discoverability, forced colors, and reduced-motion/transparency behavior are part of this design refinement rather than deferred cleanup.
- The user explicitly excluded dependencies from inspection. No `node_modules` or framework documentation pass will be added for a design-only change; the current Next.js app structure is preserved rather than modified.

## Risks / open questions
- CSS scroll-driven animations vary by browser; the feature-gated static fallback is the accepted behavior.
- The stylesheet already contains an older and an approved spatial generation. This pass will avoid adding another layer but will not fully consolidate the historical rules.
- Noticeable glass effects can reduce contrast; touched surfaces must retain solid, reduced-transparency, forced-color, and high-contrast fallbacks.

## Out of scope
- Quest copy, recommendation logic, XP math, achievement unlock rules, sound generation, evidence handling, privacy rules, location behavior, persistence, sharing, service workers, Supabase, generated assets, dependencies, deployment, and unrelated projects.
- New routes, components, animation libraries, image generation, or a wholesale stylesheet rewrite.
